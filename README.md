## Artifact 1 - Website based project portfolio

A single-page portfolio site (`docs/`, served by GitHub Pages) with hash-based routing: Home, About, All Artifacts, and a detail page per artifact. All content is generated from the `PROJECTS` array in `docs/script.js`. The devlog is in [`docs/LOG.md`](logs/LOG.md).

### Interactive terminal

A simulated shell (no real shell access, no backend) in `docs/terminal.js`. Its filesystem is built from `PROJECTS`, and `cd` changes the page, so the terminal and the site stay in sync. It opens large on Home and as a floating panel on other pages, with a `>_ Terminal` button to reopen it after closing.

- **Desktop:** type commands at the prompt. Tab completes names and ↑/↓ recalls history. `help` lists every command: `ls`, `cd`, `pwd`, `cat`, `tree`, `open`, `echo`, `history`, `clear`, `help`, `exit`. Backtick toggles the terminal.
- **Mobile:** the input is hidden so no keyboard opens, and a blinking prompt stands in for it. Use the **Commands** menu to navigate and run `ls`, `tree`, `clear` and `help`. On phones `help` only lists the commands the menu can run, so `cat`, `open`, `echo` and the like don't appear.
- `cd` accepts full paths (`cd ~/about`) from anywhere. Short artifact names (`cd artifact_2`, `cd adblock`) only work from inside `~/artifacts`.

## Artifact 2 - Ad Blocker

**AdFree** ([`AdFree/`](AdFree/)) is a sandboxed macOS app that opens YouTube and Twitch with ad blocking built in, and only the sites on an editable allowed list. It is a SwiftUI window around a `WKWebView`, so it's the real sites with your own sign-in. Blocking has three layers: network rules, a YouTube script and a Twitch script. The home page shows one card per allowed site, and sites are added or removed in Settings. Settings also has an editor for the blocking scripts and rules. The toolbar has an ads-skipped counter and an "Ads showing?" panel that walks through fixes when something breaks. Closing the window quits the app.

```bash
cd AdFree && ./build.sh run
```

Needs macOS 14+ and Xcode.

## Artifact 3 - AdFree Continued (AI Inside)

Artifact 2's **AdFree** with Claude Code inside the workflow. AdFree itself makes no AI calls and needs no API key. Instead it ships an **MCP server** (`AdFree/mcp/server.js`, plain Node, no packages) that Claude Code runs on the user's existing login. Claude Code can read AdFree's diagnostic report and a page snapshot, then change per-site block rules, edit the blocking scripts, or turn layers on and off. It decides what is wrong and writes the fix. Code checks every input, limits what can change, applies it, logs it, and every change is undoable.

An in-app chat using the user's own API key was built first and dropped: API calls bill per use, and the course access covers Claude Code, not the API. The reasoning is in the devlog.

- **Bridge:** a file mailbox in `~/.adfree/bridge`, not a network port, so the app keeps its sandbox. The only added permissions are read/write for `~/.adfree/`, read-only for `~/.claude.json` and Apple events to Terminal.
- **Settings → Claude Code:** checks whether AdFree is already connected to Claude Code, shows the right command (add, or reset if it points at another copy), and opens Terminal in the `AdFree` folder to run it or to start a working session.
- **Scope:** `AdFree/.mcp.json` registers the server when Claude Code starts in `AdFree/`, so its working folder is AdFree and its files, not the whole repo.

```bash
cd AdFree && ./build.sh run
node mcp/test.js   # 16 checks against a mock app
```

Needs macOS 14+, Xcode, Node.js and Claude Code. Status: the server passes its tests against a mock app; the full run of the real app with Claude Code is still being verified.
